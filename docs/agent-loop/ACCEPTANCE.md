## 判定规则

- `通过`：该项命令或人工步骤已实际执行，结果符合期望，并有输出、截图或明确观察记录。
- `失败`：已执行，但结果不符合期望或出现错误。
- `未验证`：未执行、环境不可用、证据缺失或只能静态推断。
- 只有所有“必须”项通过，才能建议批准本轮 Goal。
- 任一必须项失败时，报告结论不能写“完成”。
- UI、声音、手感等人工体验没有用户观察时必须写“未验证”。

## 路线专项验收

### Godot Mainline

- 记录 `godot --version` 或 `godot4 --version`。
- 用 Godot 4.x 导入并运行对应项目或场景。
- 验证受影响的移动、互动、HUD、数据、存档或其他实际行为。
- 没有 Godot 运行证据时，对运行结果写“未验证”。

### Electron Legacy

- 运行任务指定的 npm、启动或手动回归步骤。
- 检查 localStorage 兼容、金币、任务、图鉴、商店、音效和迷你模式的相关影响。
- 没有实际启动或人工观察时，对 UI、声音和交互写“未验证”。

### 文档任务

- 检查必需章节、术语和链接。
- 证明代码、配置、素材和不在范围内的文档没有被修改。
- 不用文档静态检查替代产品运行验收。
