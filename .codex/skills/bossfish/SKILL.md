# BossFish Compact Development Skill

适用项目：《老板鱼来了》 / Boss Fish Is Coming

项目类型：
Windows 小窗口 Electron 单机放置钓鱼游戏。

技术栈：
Electron、HTML、CSS、JavaScript、Canvas、JSON、localStorage。

当前没有：
后端、服务器、数据库、账号、联网、排行榜、Steam 成就。

---

## 1. 默认回答模式

使用 BossFish Compact Mode。

目标：
少废话，少重复，多边界，多命令，多验收。

回答必须包含：

1. 结论
2. 本次目标
3. 修改范围
4. 禁止范围
5. 文件责任归属
6. 影响检查
7. 验收清单
8. 未验证项
9. Git 命令

不要输出：

* 大段背景解释
* 无关科普
* 没有必要的架构长篇
* 模糊的“应该可以”
* 没证据的“已完成”

必须写明：

* 没验证的内容标注“未验证”
* 没运行不得说测试通过
* 没 commit 不得说已存档
* 没截图或人工观察不得说 UI 正常

---

## 2. 开发分支规则

从 v0.3 起允许小里程碑分支：

1. 一个大版本一个分支。
2. 一个大版本允许包含 3～6 个同主题需求。
3. 每个需求建议单独 commit。
4. 每个需求必须单独验收。
5. 高风险功能仍然单独分支。
6. 不允许把互不相关的功能混在一个版本。

禁止：

* 直接在 main 上开发
* 没测试就 merge
* 没证据就 tag
* 功能代码和无关重构混在一个 commit
* 顺手改未要求功能

## 3. 文件责任归属

main.js：
Electron 主进程，窗口创建、窗口尺寸、IPC 主进程处理。
禁止放游戏规则、金币、任务、图鉴、Canvas 绘制。

preload.js：
Electron 安全桥，只暴露白名单 API。
禁止放业务规则、DOM 操作、大量状态。

index.html：
页面结构。
禁止放大量业务逻辑。

styles/：
样式、布局、视觉。
禁止放业务判断和状态计算。

src/renderer.js：
渲染进程启动入口、模块初始化、UI 事件协调。
禁止放深层业务计算。

src/game.js：
Canvas 绘制、鱼塘、猫猫、鱼漂、视觉反馈。
禁止发任务奖励、保存金币、改商店逻辑。

src/fishing.js：
钓鱼状态机、上钩计时、随机抽鱼。
禁止保存金币、渲染图鉴、发任务奖励。

src/save.js：
localStorage 存档读写、默认存档、迁移、reset save。
禁止 Canvas 绘制、DOM 大量渲染。

src/daily-quests.js：
今日委托规则、进度、领奖、防重复领取、UI。
禁止重新计算鱼价，必须使用实际 earnedCoins。

src/bestiary.js：
图鉴 UI、解锁显示、详情展示。
禁止改金币、领奖、商店购买。

src/shop.js：
商店 UI、升级购买、升级说明。
禁止改图鉴、任务、鱼类数据。

src/disguise.js：
报表模式。
禁止真实公司信息、权限、账号、后端逻辑。

data/：
静态游戏数据。
禁止放用户存档、运行时状态。

assets/：
图片、音效等静态资源。
禁止放业务逻辑。

## 4. 存档和数据规则

当前存档使用 localStorage。

如果修改存档结构，必须说明：

1. 新字段名称
2. 默认值
3. 旧存档迁移方式
4. reset save 行为
5. 重启保留行为
6. 是否影响今日委托、图鉴、金币、商店、徽章、统计

不能直接破坏旧存档。
不能假设用户一定是新存档。

---

## 5. 代码质量规则

默认要求：

1. 能用 50 行以内函数解决，就不要写超长函数。
2. 单个函数超过 50 行必须说明原因。
3. 单个函数超过 80 行，优先拆分。
4. 同一逻辑出现 3 次，必须考虑抽函数。
5. 不为一个小需求引入大型抽象。
6. 不为一个按钮新建复杂系统。
7. 不新增依赖，除非收益明显且先说明理由。
8. 不写“以后可能用”的代码。
9. 不保留死代码、废弃函数、无用注释。
10. 不提交 console.log、debugger、临时测试代码。
11. 不提交未使用图片、未使用音效、孤立文件。
12. 不把 UI、业务、存档混在一个大函数里。
13. 不把 main.js / preload.js 当万能入口。
14. 不做“大重构式小需求”。

允许：

* 小函数
* 明确命名
* 早返回
* 简单对象映射
* 局部辅助函数
* 最小必要迁移
* 失败兜底

禁止：

* 屎山式长函数
* 无边界重构
* 魔法数字到处散落
* 重复复制粘贴
* 业务逻辑写进 CSS
* 数据写死在多个文件
* 为了“优雅”过度抽象

## 6. 代码审查规则

每次改完代码，提交前必须自查：

1. git diff --name-status
2. git diff --check
3. 检查是否有无关文件
4. 检查是否有未使用函数
5. 检查是否有重复逻辑
6. 检查是否有 console.log / debugger
7. 检查函数是否过长
8. 检查是否破坏已有模块边界
9. npm start
10. 手动验收本次需求

PowerShell 检查命令：

```powershell
git diff --name-status
git diff --check
Select-String -Path .\src\*.js -Pattern "console.log|debugger|TODO|FIXME"
```

如果发现无用代码：

* 能删就删。
* 不确定用途则标注“未验证，不删除”。
* 不允许为了看起来干净误删业务代码。

## 10. 禁止事项

当前仍然不做：

* 后端
* 账号
* 数据库
* 联网
* 排行榜
* Steam 成就
* 复杂宠物养成
* 地牢
* 合成
* 托盘
* 全局快捷键
* 复杂动画系统
* 大型重构
* 无证据完成声明

如果用户要求提速：
可以做小里程碑需求包。
但必须同主题、分 commit、逐项验收。
