# Boss Fish v0.4 Art Direction

## Purpose

Create one consistent, low-noise pixel-blockout direction for the playable Godot demo. This specification controls placeholders and future asset acceptance; it does not claim that final hand-drawn art exists.

## Visual Keywords

- Office after-hours, warm wood against cool blue-green machinery.
- Cute, compact, readable, slightly tense rather than realistic.
- Chunky silhouettes, sparse highlights, shallow depth bands, and clear interaction landmarks.
- “Secret office fishing” reads through contrast: safe teal water, amber reward, and coral boss warning.

## Pixel Scale and Rendering

- Target presentation: 1280×720.
- New world sprites should use 16 px, 32 px, 48 px, 64 px, or 96×64 cells; choose one cell size per asset family.
- UI icons should be designed on 16 px or 24 px grids and displayed at integer scale only.
- No fractional sprite scale, texture smoothing, soft shadow blur, photographic texture, or antialiased edge is accepted in the final import.
- `project.godot` must retain nearest-friendly canvas texture filtering. Per-texture imports must not override it with linear filtering.

## Palette Direction

| Role | Direction | Example use |
| --- | --- | --- |
| Ink | near-black blue charcoal | outlines, HUD frame, floor separation |
| Office base | blue-gray / desaturated teal | floor, wall, inactive panels |
| Wood | muted umber | desks, pond rim, signs |
| Water | teal to cyan | pond, fishing indicator, safe interaction |
| Reward | muted amber | coins, quest-ready, result title |
| Risk | coral-red | boss warning, inspection state |
| Collection | lavender-blue | bestiary and locked collection accent |
| Support | moss green | shop, success, active confirmation |

Use one ink color, one base, and at most two accents per object. Small light bands may establish depth; do not simulate texture with random pixels.

## Map Rules

- The office stays node-composed: floor, wall band, windows, desk row, rug, pond deck/water, and boss door remain separate scene nodes.
- Every interactable needs a recognizable silhouette, a named sign, and an accent family distinct from the other four areas.
- Walkable lanes stay visually quieter than landmarks and must not change collision ownership.
- Use deliberate 8–16 px block bands, edge trims, and sparse repeated motifs. Do not use a single full-screen AI-generated background image.
- Decorative nodes must not obscure the cat, interaction labels, prompt, status, or HUD.

## Character Rules

- The protagonist cat is a **placeholder** until a final pixel sprite sheet is approved.
- Future cat sprites use a readable 32–48 px silhouette, two or three values plus an outline, and separate facing/idle frames only when a milestone approves animation.
- A placeholder must use the approved placeholder frame and label; it must not impersonate final art.

## Fish Rules

- Fish presentation uses 96×64 source cells for the current test candidates, nearest filtering, and integer display scale.
- The gameplay IDs remain data-driven. A candidate image is an `imported` test asset only after it exists under `godot/assets/` and is listed in the manifest.
- Rare/epic/legendary distinction is an overlay/accent treatment, not a separate uncontrolled art style.
- Missing fish retain a uniform fish-card placeholder; never substitute arbitrary unrelated art silently.

## UI Rules

- HUD and modal panels share the same dark ink frame, blue-gray fill, thin accent stripe, and high-contrast text hierarchy.
- Header text is 24–28 px; primary HUD value is 20–24 px; operational/help copy is 16–18 px at 1280×720.
- Buttons use a clear border, filled state, and one action accent. Modal actions remain keyboard-closeable with Esc.
- Pressure uses coral only at warning/inspection; reward uses amber; avoid using both colors as generic decoration.

## Placeholder Versus Final

| Status | Definition | Required marking |
| --- | --- | --- |
| `placeholder` | Deliberate node-composed blockout or temporary SVG/card used to preserve layout and behavior | Listed in `ASSET_MANIFEST.md`, named with `placeholder` or documented scene node |
| `imported` | Source asset copied into `godot/assets/`, validated for size/filter/source, but not art-approved | Manifest source and review status recorded |
| `final` | Human-reviewed asset that follows this guide and has been accepted for the project | Manifest approval note and actual production path |
| `missing` | Required visual has no Godot asset yet | Manifest entry; the scene must fall back to the uniform placeholder style |

No item becomes `final` because it was generated by an external tool, copied from another prototype, or merely looks usable.

## Explicit Prohibitions

- No full-screen AI background or unreviewed generated art used as final game art.
- No random-color placeholder blocks, failed image generations, giant source files, or unreferenced assets in `godot/assets/`.
- No complex TileMap or animation system in v0.4.
